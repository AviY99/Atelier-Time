## Implementation

1. **Custom Shared Sound:** `Same sound for all → 5s / 10s / Custom` remains. **Custom shows ONLY the duration slider (5–60 seconds)**. The former `Custom sound volume` slider is removed, with no replacement. Old saved gain values are **retained harmlessly** for downgrade/backwards-data compatibility but no longer alter sound playback: `SoundSettings.playbackVolumePercentFor` returns 100% for all cues, ensuring no previously saved 0% gain silently mutes sounds after upgrading. The selected **phone Media/Alarm** volume sliders control volume instead.
2. **Flat, dense top Timer controls:** `RunningClassQuickControls.kt` no longer uses filled Surface cards, purple blocks, emoji speakers/bells, thick native Sliders or ornamental styling. Shows a plain, 48dp-accessible `Keep Screen Awake` row with `Uses more battery` caption, colored ON/OFF Switch; a simple divider; `Volumes` with original explicit-confirmation `Max both` at far right; **two draggable `AtelierSlimSlider` bars** for Media and Alarm with live percentages. Selected sound output indicated by restrained **bold/darker text and `Selected`** next to percent. Unselected row has no background. Both bars change the actual distinct Android device stream on release; selecting the text changes saved general sound output selection. Existing small gap to Class Timer retained.
3. **Free Timer:** The same component now appears above Free Countdown section, **including Keep Awake, Media/Alarm selection and TWO real volume sliders, Max both**. Shared `keepScreenAwake` and device volume controller/safety are reused. `Max both` uses the existing loud-volume confirmation; conditional restoration when Free timer is **Exited**, not at sound playback initiation. Correct warning if selected stream volume is zero. Unique accessibility tag `free_timer_quick_controls` is not overwritten by the default Run tag.
4. **Global sound control in Sounds tab:** two straightforward bottom settings: **`Sound` ON/OFF** and **`Use sound` Media/Alarm**. These replace the old `Use alarm volume for Class A/B/C` and separate duplicate transient `Timer sounds` toggle. Sound ON/OFF is now `SoundSettings.timerSoundsEnabled` (default true), **persisted** by `MelodyPreferences` and used as the same enable/disable for Class cue dispatch, Free Timer completion, preview and Class sound checks. Switching OFF also stops any already playing Class/Free cue. Media/Alarm uses the existing migration-safe `classAlertsUseAlarmVolume` persisted boolean but now routes **Free playback and Free previews** through the same stream as Class A/B/C. Run/Free selection changes the same global preference. Legacy default remains Media (false).
5. **Diagnostics and safety:** sanitized Run Diagnostic snapshots include global sound enabled and channel; no obsolete Custom gain value. No new dangerous Android permissions, no background/timer schedule logic changes, no alteration of sound melodies/patterns, saved Classes, durations, diagnostic history, artwork or existing Free audio choice.
6. **Tests:** domain `SoundSettingsTest` expanded from 15 to **17 JVM cases** including default/mode switch Global Sound ON/OFF, global Media/Alarm selection and ignoring legacy Custom sound gain; isolated AndroidTest `MelodyPreferencesTest` expanded to **10 (compile-only, not executed by local script)** with persisted global controls. Adapted old `D148SharedSoundCustomUiTest` to assert **absence** of Custom gain slider and test global selection; added `D149GlobalSoundControlsUiTest` 2 Compose methods (compile-only). Existing `D148VolumeSliderMathTest` 8 JVM and all timer/scheduling regression suites remain.
